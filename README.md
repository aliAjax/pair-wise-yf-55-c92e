# pair-wise-yf-55 动态表单规则编排和版本迁移模拟器

## 业务闭环

- 两个“标签页”使用各自的打开基准修订号编辑同一份草稿；保存时做乐观并发检查。
- 保存时发现服务端修订号已变化，会基于“打开基准 / 本页改动 / 对方最新结果”做三方合并。
- 只有一边修改的字段、联动自动采纳；同一项两边都改或一边删除一边修改时，保留双方结果并进入冲突选择。
- 字段新增、删除、改名、改类型、改必填或改选项后，引用它的联动立即重新计算；发布前展示失效或待确认原因。
- 引用字段缺失、选项值缺失的联动会被标记为失效并阻止发布。
- 已发布版本不可变；运行态提交会绑定当时版本，之后字段含义、类型或必填规则变化都不影响旧值解释。
- 迁移模拟保留已移除字段的旧值；含义变化的字段标记“仍按旧版本解释”；新版必填缺口单独列出。
- 服务端草稿、发布版本和快照持久化到 localStorage；真实浏览器标签页也会通过 `storage` 事件同步。

## 技术栈

React 19 + TypeScript + Vite + MUI + Redux Toolkit + i18next + dnd-kit。

## 并发合并验证路径

1. 在“标签页 A”修改一个字段但先不保存。
2. 切到“标签页 B”修改另一个字段并保存，服务端修订号递增。
3. 回到 A 保存：无冲突项自动合并并生成新修订号。
4. 再让 A、B 修改同一个字段或同一条联动，后保存的一侧会看到两份候选，逐项选择后才能提交。
5. 删除源字段或目标字段，联动区会立即显示失效原因并阻止发布。
